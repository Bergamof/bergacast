# Bergacast
Service auto-hébergé de publication de podcasts : des outils automatisés publient des épisodes (audio + métadonnées) via une API authentifiée par podcast ; métadonnées dans PostgreSQL ; audio, image de couverture (réduite à 3000 px) et flux RSS sont des objets publics d’un stockage objet S3 (Scaleway Object Storage), clé = chemin de l’URL publique (`{slug}.xml`, `{slug}/image.{ext}`, `{slug}/episodes/{id}/audio.{ext}`), retrouvables sans la base ; le flux est réécrit à chaque modification ; une SPA d’administration gère le tout. Production : deux images (backend natif GraalVM, frontend statique) sur Scaleway Serverless Containers. Dépôt : github.com/Bergamof/bergacast, branche principale `main`.

- Backend (`backend/`) : Java 25, Spring Boot 4.1.1 (WebMVC, Security + OAuth2 resource server/Nimbus, Data JPA, Validation, HATEOAS, Actuator, Flyway), springdoc-openapi 3.1.1, PostgreSQL 18, AWS SDK for Java v2 2.55.16 (`s3` + `url-connection-client`, sans Netty/Apache client), Gradle 9.8.2 (wrapper, Kotlin DSL), GraalVM Native Build Tools 1.1.16 (`org.graalvm.buildtools.native`, image `bergacast`, `-march=compatibility`, `-H:+StaticExecutableWithDynamicLibC`).
- Qualité backend : JUnit 5, Testcontainers 2.0.5 (via BOM Boot, images `postgres:18` et `adobe/s3mock:5.2.3`), JaCoCo 0.8.15, Spotless 8.10.4 (palantir-java-format 2.102.0 pour Java, ktlint pour `*.gradle.kts`), Checkstyle 14.3.0 (`config/checkstyle/checkstyle.xml`, `maxWarnings = 0`), javac `-Xlint:all -Werror`.
- Frontend (`frontend/`) : SvelteKit 3.1, Svelte 5.57 (runes), TypeScript 6, Vite 8, `adapter-static` (SPA à la racine, fallback `index.html`, `precompress`), Vitest 5 (+ couverture v8), ESLint 10, Prettier 3, svelte-check.
- Livraison : `backend/Dockerfile` (`ghcr.io/graalvm/native-image-community:25` → `gcr.io/distroless/base-debian13:nonroot`), `frontend/Dockerfile` (`node:24-alpine` → `joseluisq/static-web-server:2.44.1-alpine`), Docker Compose (`db` + `storage` (S3Mock) + `backend` + `frontend`), GitHub Actions (CI + publication), registry Scaleway `rg.fr-par.scw.cloud/bergacast/bergacast-{backend,frontend}`, Dependabot hebdomadaire.

## Méthode de travail
- Tâche non triviale : présenter d'abord un plan d'action (synthèse des principaux choix techniques et fonctionnels avec justification, étapes, livrables, découpage en sous-agents, risques) et attendre la validation d'Adrien avant de coder.
- Exécution : l'agent principal orchestre ; le travail est délégué à des sous-agents spécialisés à périmètre étroit (briefs autosuffisants, un propriétaire par fichier, parallèle seulement si indépendant), puis relu et vérifié. Agents du projet : `.claude/agents/` (api-rest-reviewer, test-writer, ci-fixer).
- Pas de sous-agent pour une micro-tâche.
## Définition de « done » (sauf indication contraire d'Adrien)
- Une tâche est terminée seulement quand toutes les CI déclenchées par les modifications sont vertes sur le dernier commit poussé.
- Après chaque push : surveiller les runs jusqu'à la fin ; en cas d'échec, lire les logs, corriger la cause racine, repousser, re-surveiller.
- Interdit pour obtenir le vert : skipper/désactiver un test, assouplir le lint, `continue-on-error`, supprimer un job, baisser un seuil.
- Échec non lié (flaky, infra) : relancer une fois, puis signaler. Après ~3 échecs sur le même problème : s'arrêter et exposer le diagnostic.
- CI inaccessible : annoncer « terminé localement, CI non vérifiée », jamais « done ».
- CI verte : annoncer la fin avec le lien du run, puis arrêter de surveiller la PR (pas d'attente des commentaires/reviews).
## API REST — obligatoirement RESTful
- Contrat : OpenAPI 3 généré par springdoc depuis le code (`/v3/api-docs`, `/swagger-ui.html`, publics), lintée par Spectral en CI ; versionnement : préfixe `/api/v1` ; hypermédia : HAL.
- Documentation OpenAPI obligatoire : `@Schema(description, example, defaultValue, nullable)` sur chaque champ (springdoc ignore la Javadoc), summary + description sur chaque opération, description sur chaque paramètre ; conventions communes (401/403 selon `security`, 404 si paramètre de chemin, `Location` sur 201, `If-None-Match` si 304, Problem Details) ajoutées par `config/OpenApiConventions`, `ETag` documenté via `@EntityTagged` (`web/`) ; vérifié par `config/OpenApiDocumentationIntegrationTest`.
- URIs = ressources au pluriel, kebab-case, sans verbe ; opérations métier modélisées en ressources ou `PATCH`.
- Méthodes HTTP selon leur sémantique (`POST` → `201` + `Location`, `DELETE` → `204`…) ; codes de statut précis, jamais `200` pour une erreur.
- Erreurs en Problem Details (RFC 9457) ; API sans état ; liens hypermédia ; pagination/filtre/tri par query params ; `ETag`/`If-Match`.
- Toute entorse : justifiée et consignée dans « Décisions techniques ».
- Ressources : `GET /api/v1` (racine, public, `version` du serveur + liens) ; `POST /api/v1/access-tokens` (public) ; `/api/v1/podcasts[/{slug}]` ; `/api/v1/podcasts/{slug}/api-tokens[/{id}]` ; `/api/v1/podcasts/{slug}/image` (`PUT` corps brut `image/jpeg|png` → `201`+`Location` ou `200`, `GET`, `DELETE` ; ETag `"sha256"`, lien `image` toujours présent sur le podcast) ; `POST /api/v1/podcasts/{slug}/feed-publications` (admin, sans corps : réécrit le flux → `200` + `{feedUrl, publishedAt, episodeCount}`, lien `feedPublications` sur le podcast ; `503` documenté sur chaque opération qui réécrit le flux via `web/StorageResponses`) ; `/api/v1/{slug}/episodes[/{id}]` (jeton du podcast ou admin pour GET/POST ; PATCH/DELETE admin) ; `/api/v1/admin-users[/{id}]`. Public hors API : `/robots.txt` (`Disallow: /`, `max-age` 1 jour) ; anciennes URL des médias `GET|HEAD /{slug}.xml`, `/{slug}/image.{jpg|png}`, `/{slug}/episodes/{id}/audio.{ext}` → `301` vers le même chemin sous `BERGACAST_MEDIA_BASE_URL` (`web/MediaRedirectController`, sans base). CORS sur `/api/**` uniquement (`CorsFilter` + `security/ProblemDetailsCorsProcessor` : rejet en `403` Problem Details), origines `bergacast.cors.allowed-origins`, méthodes dont `PUT`, sans credentials, en-têtes autorisés `Authorization`, `Content-Type`, `Accept`, `If-Match`, `If-None-Match`, `Idempotency-Key` (`web/ApiHeaders`), expose `ETag`/`Location`.
- Chemins centralisés dans `web/ApiPaths` (mappings, liens, règles de sécurité). PATCH = vrai JSON Merge Patch (`application/merge-patch+json`, `web/JsonMergePatch`). Validation → `422` avec `errors[{field, message}]`. `If-Match` optionnel, discordant → `412` ; `If-None-Match` → `304`.
## Architecture
- Backend package-by-feature `fr.bergadev.bergacast` : `podcast` (événements `PodcastFeedChanged`/`PodcastDeleted` publiés dans la transaction), `episode` (`EpisodePublication` : audio envoyé hors transaction puis épisode enregistré, objet supprimé si l’enregistrement échoue), `audio` (`AudioUploads` : SHA-256 puis `PutObject`), `storage` (`StorageConfiguration` : `S3Client` path-style, checksums `WHEN_REQUIRED` ; `ObjectStorage` put/delete/`discard` (échec journalisé, orphelin) ; `MediaKeys` : clés = chemins publics ; `AfterCommit` : effets sur le stockage après commit ; `PodcastObjectsCleanup`), `image` (`ImageResizer` : contrôle du format réel, plafond 50 Mpx lu dans l’en-tête avant décodage, réduction à 3000 px max, sinon octets d’origine intacts), `feed` (`FeedEpisodeSelector` pur + `RssFeedWriter`, balises `itunes:block`/`googleplay:block` sur tous les flux ; `FeedPublisher` écoute `PodcastFeedChanged` et écrit `{slug}.xml` après commit, transaction `REQUIRES_NEW`, verrou par podcast dans le processus ; échec → `FeedPublicationException` → `503`), `token` (jetons d’API), `adminuser`, `security` (chaîne de filtres, JWT, handler Problem Details), `web` (Problem Details, ETags, liens, racine, `/error`, `RobotsController` : `/robots.txt` + constantes de l’en-tête `X-Robots-Tag: noindex, nofollow` posé sur toute réponse par `SecurityConfiguration` ; `RobotsTxtPublisher` écrit `robots.txt` dans le bucket au démarrage ; `PublicUrls` : API sur `public-base-url`, médias sur `media-base-url`), `requestlog` (`RequestLogFilter` : une ligne INFO par requête `GET /x.xml 404 3ms db=yes ua="…"`, sans query string/en-têtes/IP, sondes `/actuator/health/{liveness,readiness}` non journalisées (`/actuator/health` l’est : il interroge la base) ; `db` vient de `ConnectionTrackingDataSource`, enveloppe de la `DataSource` posée par `ConnectionTrackingPostProcessor`, suivi par thread dans `ConnectionUsage`), `config` (`BergacastProperties`, OpenAPI : `OpenApiConfiguration` + `OpenApiConventions`, `Clock`, `NativeImageHintsConfiguration` + `ImageProcessingHints` : hints GraalVM manquants), image du podcast dans `podcast/PodcastImage*` (métadonnées en base, contenu dans le bucket).
- Migrations Flyway : `backend/src/main/resources/db/migration` (`V1__create_schema.sql`, `V2__create_podcast_image.sql`, `V3__move_media_to_object_storage.sql` : anciennes colonnes de contenu rendues facultatives, conservées jusqu’à l’export ; `ddl-auto: validate`).
- Tests : `backend/src/test/...` ; `support/IntegrationTest` + `TestcontainersConfiguration` (postgres:18 + S3Mock, bucket `bergacast`) + `ApiTestClient` + `StoredObjects` (lecture des objets du bucket) ; `config/OpenApiSpecExportTest` alimente `generateOpenApiSpec`.
- Release : `.github/scripts/` (`release-plan.sh`, `release-notes.sh`, `check-pr-title.sh`, classification partagée `conventional-commits.bash`, tests bats dans `tests/`).
- Frontend : `src/lib/version.ts` (`__BERGACAST_VERSION__`, `define` Vite depuis package.json), `src/lib/runtime-config.ts` + `/config.js` (URL de l’API à l’exécution, `globalThis.bergacastConfig`), `src/lib/api` (client typé, HAL, Problem Details, `apiOrigin`), `src/lib/auth` (JWT en `sessionStorage`), `src/lib/forms`, `src/lib/format`, `src/lib/components`, `src/routes` (`login`, groupe `(app)` authentifié). Config SvelteKit dans `vite.config.ts`.
- Image backend : exécutable natif seul sur distroless `nonroot`, pas de shell ni de HEALTHCHECK (sonde de la plateforme sur `/actuator/health/liveness`, sans accès à la base), port `PORT`.
- Image frontend : `frontend/docker/docker-entrypoint.sh` écrit `config.js` depuis `BERGACAST_API_URL` (obligatoire, origine http(s) validée) puis lance static-web-server (`frontend/docker/static-web-server.toml` : `no-cache` et `X-Robots-Tag: noindex, nofollow` partout, `static/robots.txt` `Disallow: /`, `immutable` sous `/_app/immutable`, en-têtes de sécurité, fichiers précompressés, `/health`) ; fichiers en lecture seule sauf `config.js` (uid `sws`).
## Modèle de domaine
- **Podcast** : id uuid, slug (unique, immuable, `^[a-z0-9]+(-[a-z0-9]+)*$`, ≤ 64, réservés dans `podcast/Slugs`), title*, description*, author, ownerName, ownerEmail, language* (BCP-47), category, explicit, imageUrl, websiteUrl, réglages de flux (`maxEpisodes` ≥ 1 ou null, `evictOldestBy`, `sortBy` ∈ `PUBLICATION_DATE|ADDED_DATE`, `sortDirection` ∈ `DESC|ASC`, `includeFutureEpisodes`), createdAt, updatedAt, version.
- **Episode** : id, podcast, guid (unique par podcast, défaut UUID), title*, description, publicationDate (défaut maintenant), addedAt, durationSeconds, season, episodeNumber, episodeType (`FULL|TRAILER|BONUS`), explicit (nullable), audioFile (1:1), idempotencyKey (unique par podcast), version.
- **PodcastImage** : podcast_id (PK, FK `ON DELETE CASCADE`), mimeType (`image/jpeg|png`), width, height, sizeBytes, sha256 ; contenu : objet `{slug}/image.{jpg|png}`. Ajout/remplacement/suppression → incrémente la `version` du podcast. Flux : `itunes:image` = image envoyée, sinon `imageUrl` (externe), sinon rien.
- **AudioFile** : id, mimeType, sizeBytes, sha256, fileExtension ; contenu : objet `{slug}/episodes/{episodeId}/audio.{ext}` (id d’épisode attribué par l’application avant l’envoi).
- **ApiToken** : id, podcast, name, tokenHash (SHA-256, unique), tokenPrefix (8 car.), createdAt, lastUsedAt ; format `bgc_` + 32 octets base64url, montré une seule fois.
- **AdminUser** : id, username unique, passwordHash (encodeur délégant), createdAt ; mot de passe ≥ 12 caractères.
- Flux (calculé à chaque écriture) : tous les épisodes → sans `includeFutureEpisodes`, `publicationDate <= now` → si `maxEpisodes`, garder les N plus récents selon `evictOldestBy` → tri `sortBy`/`sortDirection` (départage : autre date, puis id).
- Cascades : suppression podcast → épisodes et jetons (FK `ON DELETE CASCADE`) puis, après commit, objets `{slug}.xml` et `{slug}/*` ; trigger : suppression épisode → `audio_file` (→ `lo_unlink` de l’ancien contenu s’il existe) ; objet audio supprimé après commit.
## Décisions techniques
- 2026-10-22 — Java 25 (LTS en cours, Temurin), Spring Boot 4.1.1, Gradle 9.8.2, Node 24 LTS, npm 12.2.1, PostgreSQL 18.
- 2026-10-27 — Médias et flux sur stockage objet S3 (Scaleway Object Storage, décision d’Adrien) au lieu des large objects/`bytea` : les applis d’écoute ne réveillent plus ni le conteneur ni la base serverless, `Range`/ETag/cache fournis par le stockage. Clé = chemin de l’URL publique, déduite du slug (et de l’id d’épisode) : tout objet se retrouve sans la base. Lecture publique par *bucket policy*, écriture par le seul backend (clé IAM). Contreparties : deux choses à sauvegarder ; pas de transaction commune → objet écrit avant le commit (audio : hors transaction puis épisode ; image : dans la transaction après revérification), suppressions après commit, échec = orphelin journalisé (`discard`). Client : AWS SDK v2 + `url-connection-client` (natif léger), path-style, checksums `WHEN_REQUIRED` (S3 hors AWS). Tests et compose : Adobe S3Mock (MinIO ne publie plus d’images communautaires).
- 2026-10-27 — Flux RSS écrit « en dur » dans le bucket à chaque modification du podcast, de son image ou de ses épisodes (décision d’Adrien), après commit. Limite acceptée (utilisateur unique) : un épisode programmé n’apparaît qu’à l’écriture suivante après sa date ; `POST …/feed-publications` réécrit à la demande. Écritures d’un flux sérialisées par un verrou local : une seule instance du backend (`max-scale` 1) ; verrou consultatif PostgreSQL écarté (non garanti sur Serverless SQL). Entorses REST : (1) échec d’écriture du flux après commit → `503` alors que la modification est enregistrée (signal visible plutôt qu’un flux silencieusement en retard), documenté sur chaque opération concernée, le détail dit de ne pas rejouer mais de réécrire le flux ; un rejeu par `Idempotency-Key` réécrit le flux ; (2) `POST …/feed-publications` → `200` sans `self` ni `Location`, comme `access-tokens` : la publication n’est pas une ressource adressable, l’URL du flux est dans le corps.
- 2026-10-27 — Anciennes URL publiques du backend (flux, image, audio) gardées en redirection `301` vers le bucket (abonnés existants), sans accès à la base. Migration en deux temps : `V3` garde l’ancien contenu, script d’export, puis migration ultérieure (`lo_unlink`, suppression des colonnes) une fois l’export vérifié.
- 2026-10-22 — Parts multipart écrites sur disque (`file-size-threshold: 0`) : l’audio n’est jamais tenu en mémoire (SHA-256 puis envoi au stockage en relisant le fichier).
- 2026-10-22 — ETags forts : podcast `"version.episodeCount"`, épisode `"version"` ; flux, audio et image : ETag du stockage.
- 2026-10-22 — Slug immuable (URL de flux et d’audio stables pour les agrégateurs) ; noms réservés pour ne pas masquer une route.
- 2026-10-22 — URL de publication `/api/v1/{slug}/episodes` (demande d’Adrien) ; ambiguïté avec `/api/v1/podcasts/...` levée en excluant `podcasts|admin-users|access-tokens` du `{slug}` de la route épisodes (`ApiPaths.EPISODES_MAPPING`) + slugs réservés.
- 2026-10-22 — Entorse REST : `POST /api/v1/access-tokens` → `200` (pas `201`) : le jeton n’est pas une ressource adressable, comme un endpoint token OAuth2.
- 2026-10-22 — Jetons d’API par podcast stockés hachés SHA-256 (aléa de 32 octets : pas besoin de bcrypt), autorité limitée aux épisodes de leur podcast.
- 2026-10-22 — JWT admin HS256 15 min via Spring Security resource server (Nimbus), secret ≥ 32 octets obligatoire (échec au démarrage). Sans état : pas de révocation (limite assumée).
- 2026-10-22 — OpenAPI et Swagger UI publics en production (demande d’Adrien, pour brancher des outils externes).
- 2026-10-24 — SPA séparée du backend (une image par module, Scaleway Serverless Containers = un domaine par conteneur) : appels directs à l’API en CORS plutôt qu’un proxy dans le conteneur frontend (uploads de 500 Mo non doublés, pas de double démarrage à froid). URL de l’API à l’exécution (`config.js`) : une image pour tous les environnements. Pas de CSP (script inline de l’index SvelteKit).
- 2026-10-24 — Backend en natif GraalVM (CE 25) : mémoire et démarrage minimaux en serverless (scale-to-zero) ; Leyden/CDS écartés (gain au démarrage seulement). Vérifié par un smoke test HTTP de bout en bout (pas de `nativeTest` : Testcontainers incompatible en natif). Frontend : static-web-server (Rust, ~18 Mo, ~10 Mo RAM) plutôt que nginx/Caddy.
- 2026-10-24 — `-Xlint:all -Werror` et Checkstyle limités au code écrit à la main (`compileJava`/`compileTestJava`, source sets `main`/`test`) : le code généré par Spring AOT produit des warnings `rawtypes`/`unchecked`.

## Pièges et conventions spécifiques
- Natif : une réflexion manquante n’échoue qu’à l’exécution (`MissingReflectionRegistrationError`) → ajouter le hint dans `config/NativeImageHintsConfiguration` (+ test), reconstruire l’image, relancer `smoke-test.sh`. Avertissements Flyway « Unable to scan location … unsupported protocol: resource » au démarrage natif : bénins (les migrations sont trouvées par Spring Boot).
- Natif + ImageIO/AWT : les `.so` JNI émis par native-image (`libawt`, `libawt_headless`, `libjavajpeg`, `liblcms`, `libjava`, `libjvm`) doivent être copiés à côté de l’exécutable (`backend/Dockerfile`, liste explicite ; `libawt_xawt`/`libfontmanager` exclus : X11/freetype absents) + hints JNI dans `config/ImageProcessingHints` (générés avec l’agent de traçage).
- `./gradlew test` exécute aussi `processTestAot` (plugin natif) : démarre chaque contexte de test en AOT (Docker requis).
- Scaleway Serverless SQL (base de prod) : verrous consultatifs Flyway « non garantis » ; les large objects existants y fonctionnent (ancien contenu, exporté par le script).
- Scaleway Object Storage : une *bucket policy* ne laisse passer que les principaux listés (y inclure l’application IAM du backend) ; S3 ne peut pas ajouter `X-Robots-Tag` → `robots.txt` écrit à la racine du bucket.
- `AfterCommit` : une exception levée après commit remonte à l’appelant (transaction déjà validée) et empêche les synchronisations suivantes → enregistrer les nettoyages avant l’écriture du flux. Lire en base depuis un callback après commit exige une nouvelle transaction (`REQUIRES_NEW`).
- Bac à sable cloud : Docker Hub et Maven Central limités (429), ghcr/Oracle bloqués → images via `mirror.gcr.io/...` retaguées, miroir Maven Google dans `~/.gradle/init.d` (local, jamais commité), pas de build natif local (vérifié par la CI).
- Maven Central renvoie parfois HTTP 429 : réessayer (retries configurés dans `backend/gradle.properties`).
- Testcontainers exige Docker, y compris pour `./gradlew generateOpenApiSpec` (démarre l’application).
- springdoc : le customizer HATEOAS passe après les nôtres et remplace les schémas `Link`/`Links` (descriptions impossibles, exclus du test) ; un enum nullable ne peut pas être `nullable = true` (JSON Schema invalide) : le dire dans la description.
- Partie `metadata` de l’upload : lue brute (`episode/EpisodeMetadataReader`), acceptée sans type, `text/plain`, `application/octet-stream`, `application/json` ou `*+json` (outils type n8n/Zapier) ; JSON invalide → 400, validation → 422.
- SvelteKit 3 : pas de `svelte.config.js` (config dans `vite.config.ts`) ; imports `#lib/*` (champ `imports` de package.json) avec extension explicite au lieu de `$lib` ; `resolve()` de `$app/paths` prend l’id de route avec groupe (`resolve('/(app)/podcasts')`).
- `@vitest/coverage-v8` a `vitest` en peer exact : toujours les monter ensemble (groupe Dependabot `vitest`).
- `engine-strict=true` : Node ≠ 24 ou npm ≠ 12.2.1 → `npm ci` échoue ; installer `npm install -g npm@12.2.1`.
- Spotless formate aussi les `*.gradle.kts` (ktlint) : lancer `spotlessApply` après toute modif du build.
- Checkstyle : `MagicNumber` actif en production, désactivé seulement dans les tests ; zéro avertissement toléré.
- javac `-Werror` avec `-Xlint:all` : tout warning de compilation casse le build.
- Ports : 8080 (backend), 5173 (Vite), 5432 (base de dev) ; conflit fréquent avec un autre PostgreSQL/une autre app → libérer le port ou changer `BERGACAST_PORT`/`SPRING_DATASOURCE_URL`.
- `docker compose` exige un `.env` (`POSTGRES_PASSWORD`, `BERGACAST_JWT_SECRET` en `:?`) même pour démarrer seulement `db`.
- Volume PostgreSQL 18 monté sur `/var/lib/postgresql` (et non `/var/lib/postgresql/data`).
- La `DataSource` injectée est l'enveloppe `requestlog/ConnectionTrackingDataSource` : injecter `DataSource` puis `unwrap(HikariDataSource.class)` pour accéder au pool (un `@Autowired HikariDataSource` échoue).
- `/api/v1/**` non autorisé → `401` + `WWW-Authenticate: Bearer` ; jeton d’un autre podcast → `403`.

Jamais pousser sur `main` ni sur une branche d'autrui.

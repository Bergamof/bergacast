- 2026-10-27 — Médias et flux sur stockage objet S3 (Scaleway Object Storage, décision d’Adrien) au lieu des large objects/`bytea` : les applis d’écoute ne réveillent plus ni le conteneur ni la base serverless, `Range`/ETag/cache fournis par le stockage. Clé = chemin de l’URL publique, déduite du slug (et de l’id d’épisode) : tout objet se retrouve sans la base. Lecture publique par *bucket policy*, écriture par le seul backend (clé IAM). Contreparties : deux choses à sauvegarder ; pas de transaction commune → objet écrit avant le commit (audio : hors transaction puis épisode ; image : dans la transaction après revérification), suppressions après commit, échec = orphelin journalisé (`discard`). - 2026-10-27 — Flux RSS écrit « en dur » dans le bucket à chaque modification du podcast, de son image ou de ses épisodes (décision d’Adrien), après commit. Limite acceptée (utilisateur unique) : un épisode programmé n’apparaît qu’à l’écriture suivante après sa date ; `POST …/feed-publications` réécrit à la demande. Écritures d’un flux sérialisées par un verrou local : une seule instance du backend (`max-scale` 1) ; verrou consultatif PostgreSQL écarté (non garanti sur Serverless SQL). Entorses REST : (1) échec d’écriture du flux après commit → `503` alors que la modification est enregistrée (signal visible plutôt qu’un flux silencieusement en retard), documenté sur chaque opération concernée, le détail dit de ne pas rejouer mais de réécrire le flux ; un rejeu par `Idempotency-Key` réécrit le flux ; (2) `POST …/feed-publications` → `200` sans `self` ni `Location`, comme `access-tokens` : la publication n’est pas une ressource adressable, l’URL du flux est dans le corps.

- 2026-11-02 — Connexion admin limitée par identifiant (décision d’Adrien) : 3 échecs consécutifs → `429` + `Retry-After` pendant 10 s, doublé à chaque nouvel échec, plafonné à 1 h (plafond technique), remis à zéro par une connexion réussie ; tentatives pendant le blocage refusées sans vérifier le mot de passe (pas de coût bcrypt) et sans prolonger le blocage ; chaque tentative réservée avant la vérification (requêtes simultanées : jamais plus que les essais gratuits, puis une seule à la fois) ; seul `BadCredentialsException` compte (base indisponible ≠ échec) ; identifiants inconnus traités pareil (pas d’énumération) ; identifiant ≤ 100 caractères et mot de passe ≤ 72 (`422`). En mémoire (instance unique, redémarrage = oubli), au-delà de 10 000 identifiants les moins récents oubliés, jamais un blocage en cours. Contrepartie assumée : qui connaît un identifiant peut le bloquer (au plus 1 h, renouvelable en attendant chaque fin de blocage) ; IP non utilisée (`X-Forwarded-For` falsifiable). Corps JSON de l’API (et partie `metadata` de l’upload) limités à 256 Kio (`413`, y compris sans `Content-Length` : l’échec enveloppé par Jackson est rendu en `413`) : descriptions en `text` sans limite en base, notes d’épisode HTML possiblement > 64 Kio. `FormContentFilter` désactivé (`spring.mvc.formcontent.filter.enabled: false`) : il lisait sans limite, avant l’authentification, les corps de formulaire `PUT`/`PATCH`/`DELETE` (OOM vérifié) ; l’API n’a aucun formulaire.
- 2026-11-02 — Expiration du JWT admin (15 min, sans rafraîchissement : API sans état) : la SPA redemande le mot de passe dans une fenêtre modale 1 min avant l’expiration, et encore après, sans quitter la page (travail et envoi en cours conservés ; WCAG 2.2.1) ; endpoint de rafraîchissement écarté (décision d’Adrien). - 2026-11-09 — Migrations de schéma sorties du backend (décision d’Adrien) : Liquibase 4.x (Flyway abandonné : migrations « avancées » en Java, manipulation d’objets), dans le module `migration/` lancé comme **Serverless Job** Scaleway ; le backend ne migre plus et ne valide plus le schéma au démarrage (une base serverless peut rester en pause). Liquibase 5+ écarté : licence FSL non compatible AGPL (Dependabot ignore ses majeures). Base de production : le schéma de référence reproduit Flyway V1–V4 et est noté « joué » (test de schéma identique + base héritée), `flyway_schema_history` supprimée ensuite. Verrou Liquibase = ligne de `DATABASECHANGELOGLOCK` (pas de verrou consultatif PostgreSQL, non garanti sur Serverless SQL). Contrepartie : un backend déployé sans le job tourne sur l’ancien schéma (erreurs SQL à l’usage, pas au démarrage). L’administrateur initial n’est plus créé par le backend au démarrage mais par le job (s’il n’en existe aucun), pour qu’un redémarrage du backend ne touche jamais la base.
- 2026-11-09 — Release manuelle avec déploiement (décision d’Adrien) : lancée à la main depuis `main` (`workflow_dispatch` seul), elle exige la CI verte du commit de tête (attendue si en cours), calcule la version sur tous les commits depuis le dernier tag, ne publie que les modules modifiés (migration, backend, frontend), lance le job de migration puis redéploie le backend avant le frontend, et pose le tag en dernier (un échec de déploiement se rejoue avec la même version). Clé IAM de déploiement distincte de celle du registry, dans l’environnement `production` (relecteurs possibles). API Scaleway en REST (pas de binaire `scw` à télécharger et à épingler). Limite : l’état `ready` d’un conteneur peut précéder le début du déploiement, d’où un délai de grâce (`DEPLOY_GRACE_SECONDS`) et le contrôle de l’image servie ; comportement à confirmer sur le premier vrai déploiement.
- 2026-11-11 — Image facultative d’épisode (demande d’Adrien) : `PUT|GET|DELETE /api/v1/{slug}/episodes/{id}/image` (administrateur seul : les jetons de podcast ne servent qu’à publier) et partie multipart facultative `image` à la publication (jeton ou administrateur). Métadonnées en colonnes facultatives de `episode` (type embarqué) plutôt qu’en table séparée : relation 1:1 toujours lue avec l’épisode, pas de requête en plus sur les listes ; l’ETag de l’image est son SHA-256, celui de l’épisode change (version). Image de la publication contrôlée avant l’envoi de l’audio (un fichier invalide ne coûte pas 500 Mo d’envoi) ; partie vide ignorée ; rejeu par `Idempotency-Key` : l’image du rejeu est ignorée comme l’audio. Écrire l’objet avant le commit laisse un orphelin si le commit échoue (même limite que l’image de podcast).

# Architecture et modèle de domaine

À lire avant de modifier le code backend, la migration ou la SPA.

## Architecture

- Backend package-by-feature `fr.bergadev.bergacast` :
  - `podcast` (événements `PodcastFeedChanged`/`PodcastDeleted` publiés dans la transaction ; image du podcast dans `PodcastImage*` : métadonnées en base, contenu dans le bucket), `episode` (`EpisodePublication` : image facultative vérifiée avant l’audio, audio envoyé hors transaction, image écrite, puis épisode enregistré, objets supprimés si l’enregistrement échoue ; `EpisodeMetadataReader` ; image d’épisode : `EpisodeImage` (type embarqué), `EpisodeImages` (contrôle, réduction, écriture), `EpisodeImageService`/`Controller`), `audio` (`AudioUploads` : SHA-256 puis `PutObject`), `token` (jetons d’API), `adminuser` ;
  - `storage` (`StorageConfiguration` : `S3Client` path-style, checksums `WHEN_REQUIRED` ; `ObjectStorage` put/delete/`discard` (échec journalisé, orphelin) ; `MediaKeys` : clés = chemins publics ; `MediaCacheControl` ; `AfterCommit` : effets sur le stockage après commit ; `PodcastObjectsCleanup`) ;
  - `image` (`ImageResizer` : un décodage à la fois, contrôle du format réel, plafond 50 Mpx lu dans l’en-tête avant décodage, réduction à 3000 px max, sinon octets d’origine intacts) ;
  - `feed` (`FeedEpisodeSelector` pur + `RssFeedWriter` ; `FeedPublisher` écoute `PodcastFeedChanged` et écrit `{slug}.xml` après commit, transaction `REQUIRES_NEW`, verrou par podcast dans le processus ; échec → `FeedPublicationException` → `503`) ;
  - `security` (chaîne de filtres, JWT, handler Problem Details, CORS, `LoginThrottle` : limitation des connexions par identifiant, en mémoire), `web` (Problem Details, ETags, `ImageUploads`, liens, racine, `/error`, `JsonRequestSizeFilter` : corps JSON ≤ 256 Kio, `RobotsHeaders` : `X-Robots-Tag` posé sur toute réponse par `SecurityConfiguration` ; `MediaRedirectController` (anciennes URL, dépend de `storage/MediaKeys`), `PublicUrls` : API sur `public-base-url`, médias sur `media-base-url`) ;
  - `requestlog` (`RequestLogFilter` : une ligne INFO par requête `GET /x.xml 404 3ms db=yes ua="…"`, sans query string/en-têtes/IP, sondes `/actuator/health/{liveness,readiness}` non journalisées (`/actuator/health` l’est : il interroge la base) ; `db` vient de `ConnectionTrackingDataSource`, enveloppe de la `DataSource` posée par `ConnectionTrackingPostProcessor`, suivi par thread dans `ConnectionUsage`) ;
  - `config` (`BergacastProperties`, `OpenApiConfiguration` + `OpenApiConventions`, `ClockConfiguration`, `MultipartConfiguration`, `NativeImageHintsConfiguration` + `ImageProcessingHints` : hints GraalVM manquants).
- Migrations : module `migration/` (Liquibase, `MigrationMain` lit `BERGACAST_DATASOURCE_URL/USERNAME/PASSWORD`, `Migrator`, `DatabaseSettings`) ; *changelog* `src/main/resources/db/changelog/db.changelog-master.yaml` + `changes/` (`0001` schéma de référence = ancien Flyway V1–V4, noté `MARK_RAN` sur une base déjà migrée, `0002` supprime `flyway_schema_history`, `0003` colonnes `image_*` facultatives de `episode`) ; image lancée comme job Scaleway avant le redéploiement du backend, donc migrations compatibles avec le backend précédent (ajouter, supprimer à la release suivante). Backend : `ddl-auto: none`, `spring.jpa.database: postgresql`, `allow_jdbc_metadata_access: false`, aucune migration ; ses tests construisent le schéma avec le module (`includeBuild("../migration")` dans `settings.gradle.kts`, seulement si le dossier existe : le Docker du backend n’a que `backend/`) et gardent `ddl-auto: validate` (annotation `IntegrationTest`).
- Tests : `backend/src/test/...` (package miroir) ; `support/IntegrationTest` + `TestcontainersConfiguration` (postgres:18 + S3Mock, bucket `bergacast`) + `ApiTestClient` + `StoredObjects` (lecture des objets du bucket) ; `config/OpenApiSpecExportTest` alimente `generateOpenApiSpec`.
- Release : `.github/scripts/` (`release-plan.sh`, `release-notes.sh`, `check-pr-title.sh`, `wait-for-ci.sh`, `run-migration-job.sh`, `deploy-container.sh`, `scaleway.bash`, classification partagée `conventional-commits.bash`, tests bats dans `tests/` avec `stub_command` pour `gh` et `curl`).
- Frontend `src/lib` : `version.ts` (`__BERGACAST_VERSION__`, `define` Vite depuis package.json), `runtime-config.ts` + `/config.js` (URL de l’API à l’exécution, `globalThis.bergacastConfig`), `api` (client typé, HAL, Problem Details, `apiOrigin` ; `upload-transport.ts` : envoi par XMLHttpRequest pour suivre la progression, annulable par `AbortSignal` ; connexion envoyée sans jeton), `auth` (JWT en `sessionStorage` ; `session-renewal.ts` + `components/SessionRenewalDialog` : mot de passe redemandé 1 min avant l’expiration, sur place ; expiration retenue 5 s avant celle du serveur ; `unauthorized-gate.ts` : un 401 de fond ne déconnecte pas tant que la fenêtre est ouverte, données rechargées (`invalidateAll`) après renouvellement, déconnexion sinon), `forms` (`cover-image.ts` : règles et conseils des images de couverture, podcast et épisode ; `file-input.ts`), `format`, `publishing` (exemple curl, message de réécriture du flux, `upload-tracker.svelte.ts` : progression de l’envoi audio, annonce tous les 10 %, annulation tant que le fichier part), `components` (`CoverImageForm` : image de podcast et d’épisode, textes passés en snippets ; accessibilité : `PendingButton` (`aria-disabled`, garde le focus), `StatusMessage` (région `role=status` toujours présente), `ModalDialog` (`alertdialog` commun ; non fermable pendant une requête ou une fois la session expirée), `RecoveryActions` (412 → recharger, 503 → réécrire le flux), `ErrorPageContent` des pages d’erreur avec « Réessayer »), `forms/editable-form.svelte.ts` (formulaire d’édition rechargé après succès ou 412), `forms/focus.ts`, `forms/recovery-action.ts`, `api/change-then-refresh.ts` (données rechargées après une modification, aussi sur 503 : elle peut être enregistrée), `testing` (`fake-fetch.ts`, `fake-control-container.ts`) ; `src/routes` (`login`, groupe `(app)` authentifié : `podcasts`, `admin-users`). Config SvelteKit dans `vite.config.ts`. Audit Lighthouse : `frontend/lighthouse/` (`server.mjs` sert le build avec les en-têtes de l’image, `fake-api.mjs` : API simulée HAL (l’épisode `ep-2` a une image), `405` pour toute écriture non gérée (les parcours interceptent les leurs avec `page.route`) ; `--signed-in` écrit la session dans `config.js` car `sessionStorage` est propre à l’onglet ; chaque requête d’API journalisée pour la CI) ; à tenir à jour si les ressources de l’API changent.
- Image migration : JARs Liquibase + application et JRE réduit par `jlink` (liste de modules dans le Dockerfile, à compléter si une `NoClassDefFoundError` apparaît) sur `distroless/base-debian13` comme le backend (les images distroless Java ajoutent expat/util-linux, CVE hautes sans correctif : Trivy échouait), pas de shell (classpath `/app/lib/*` développé par la JVM), code de sortie 0/1.
- Image backend : exécutable natif seul sur distroless `nonroot`, pas de shell ni de HEALTHCHECK (sonde de la plateforme sur `/actuator/health/liveness`, sans accès à la base), port `PORT`.
- Image frontend : `frontend/docker/docker-entrypoint.sh` écrit `config.js` depuis `BERGACAST_API_URL` (obligatoire, origine http(s) validée) puis lance static-web-server (`frontend/docker/static-web-server.toml` : `no-cache` et `X-Robots-Tag: noindex, nofollow` partout, `static/robots.txt` `Disallow: /`, `immutable` sous `/_app/immutable`, en-têtes de sécurité, fichiers précompressés, `/health`) ; fichiers en lecture seule sauf `config.js` (uid `sws`).

## Modèle de domaine

- **Podcast** : id uuid, slug (unique, immuable, `^[a-z0-9]+(-[a-z0-9]+)*$`, ≤ 64, réservés dans `podcast/Slugs`), title*, description*, author, ownerName, ownerEmail, language* (BCP-47), category, explicit, imageUrl, websiteUrl, réglages de flux (`maxEpisodes` ≥ 1 ou null, `evictOldestBy`, `sortBy` ∈ `PUBLICATION_DATE|ADDED_DATE`, `sortDirection` ∈ `DESC|ASC`, `includeFutureEpisodes`), createdAt, updatedAt, version.
- **Episode** : id, podcast, guid (unique par podcast, défaut UUID), title*, description, publicationDate (défaut maintenant), addedAt, durationSeconds, season, episodeNumber, episodeType (`FULL|TRAILER|BONUS`), explicit (nullable), audioFile (1:1), idempotencyKey (unique par podcast), version.
- **PodcastImage** : podcast_id (PK, FK `ON DELETE CASCADE`), mimeType (`image/jpeg|png`), width, height, sizeBytes, sha256 ; contenu : objet `{slug}/image.{jpg|png}`. Ajout/remplacement/suppression → incrémente la `version` du podcast. Flux : `itunes:image` = image envoyée, sinon `imageUrl` (externe), sinon rien.
- **Image d’épisode** (facultative) : colonnes `image_mime_type|width|height|size_bytes|sha256` de `episode` (type embarqué `EpisodeImage`, toutes nulles sans image, contrainte « tout ou rien ») ; contenu : objet `{slug}/episodes/{id}/image.{jpg|png}`. Même traitement que l’image de podcast (JPEG/PNG, 3000 px, 50 Mpx). Ajout/remplacement/suppression → `version` de l’épisode incrémentée. Flux : `itunes:image` de l’item, sinon rien (les applis reprennent l’image du podcast).
- **AudioFile** : id, mimeType, sizeBytes, sha256, fileExtension ; contenu : objet `{slug}/episodes/{episodeId}/audio.{ext}` (id d’épisode attribué par l’application avant l’envoi).
- **ApiToken** : id, podcast, name, tokenHash (SHA-256, unique), tokenPrefix (8 car.), createdAt, lastUsedAt ; format `bgc_` + 32 octets base64url, montré une seule fois.
- **AdminUser** : id, username unique, passwordHash (encodeur délégant), createdAt ; mot de passe ≥ 12 caractères.
- Flux (calculé à chaque écriture) : tous les épisodes → sans `includeFutureEpisodes`, `publicationDate <= now` → si `maxEpisodes`, garder les N plus récents selon `evictOldestBy` → tri `sortBy`/`sortDirection` (départage : autre date, puis id).
- Cascades : suppression podcast → épisodes et jetons (FK `ON DELETE CASCADE`) puis, après commit, objets `{slug}.xml` et `{slug}/*` ; trigger : suppression épisode → `audio_file` ; objets audio et image supprimés après commit.
